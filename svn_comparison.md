# SVN vs Git — сравнение

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на коммит (файл размером ~40 байт).
Создание ветки не копирует файлы, а только создаёт ссылку.
Поэтому ветки создаются мгновенно, и их можно делать сколько угодно.

В SVN ветка — это копия директории в репозитории (по сути, отдельная папка
в структуре `branches/`). Создание ветки требует копирования файлов на сервере,
что занимает время и место. Поэтому ветвление в SVN дорогое.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: все коммиты уходят на центральный сервер.
Без подключения к серверу коммит невозможен.
Можно делать локальные изменения, но зафиксировать их (commit) — только онлайн.

В Git коммит делается локально: у каждого разработчика своя полная копия
репозитория. Интернет нужен только для push/pull.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты в госсекторе и банках: там SVN уже развёрнут, миграция дорогая.
- Очень большие бинарные файлы (например, дизайн-ассеты), где Git плохо работает
  из-за размера .git. SVN хранит файлы по версиям и не тянет всю историю локально.
- Простые проекты с линейной историей и малой командой, где не нужны ветки.
- Жёсткая централизация: компании, где нужен полный контроль над доступом к репозиторию.
